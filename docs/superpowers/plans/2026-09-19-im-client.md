# iM 조건체크 Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Build and deploy a mobile-first iM 조건체크 client that presents V1/V2 loan-condition comparison, review-gated decisions, and integrity proof using the provided Figma and iM Server API.

**Architecture:** A Next.js App Router app owns the user journey and calls a same-origin /api/im/* proxy, which forwards to server-only IM_API_BASE_URL. A typed repository selects real API data in live mode or deterministic demo data in default demo mode. Route-level screens share compact display components; all financial calculations and final decision authority remain on the backend.

**Tech Stack:** Next.js 16, React 19, TypeScript, pnpm 10, Tailwind CSS, Vitest, @mingyeongbin/frontprep@0.1.0-beta.2, Lucide React, Vercel.

**Spec:** docs/superpowers/specs/2026-09-19-im-client-design.md

## Global Constraints

- Use Node.js >=22.22.1, pnpm 10, and a root-level Next.js 16 App Router TypeScript app.
- Run @mingyeongbin/frontprep@0.1.0-beta.2 only after a clean bootstrap commit; do not add another linter, formatter, test runner, UI kit, or state library.
- Keep IM_API_BASE_URL server-only; browser code may call /api/im/* only.
- Default to NEXT_PUBLIC_DEMO_MODE=true; with false, a failed backend call must show an error instead of sample data.
- Use the API success/data/error wrapper, preserve server-provided comparison values, and do not compute or approve loan terms in the client.
- Match the Figma mobile visual language: white canvas, teal primary action, rounded cards, explicit text labels for every comparison status, and bottom fixed action areas.
- Work and commit directly on main, as requested.

## Review Focus

- A malformed or unsuccessful API wrapper must produce readable error copy, never undefined financial values; test in Task 3.
- Live mode must never fall back to demo data after a server error; test in Task 4.
- A required-review item must keep agreement disabled until every required item is confirmed; test in Task 7.
- A FAILED or UNCERTAIN comparison must offer recovery/context rather than redirecting as complete; test in Task 6.
- Currency, signed deltas, percent points, and invalid dates must remain legible in Korean; test in Task 2.

\`\`\`ts
export function unwrapApi<T>(body: unknown): T {
  if (!isEnvelope(body)) throw new Error("서버 응답 형식이 올바르지 않습니다.");
  if (!body.success) throw new Error(body.error?.message ?? "요청을 처리하지 못했습니다.");
  return body.data as T;
}
\`\`\`

The route accepts only Next path segments, forwards query strings and JSON bodies, removes client-supplied host/cookie headers, uses an upstream timeout, and returns a Korean 503 JSON error when IM_API_BASE_URL is absent or unreachable.
